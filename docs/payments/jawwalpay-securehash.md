# جوال باي: خطأ 1004 «Bad SecureHash»

**التاريخ:** 2026-09-24

## ما حدث

```
production.WARNING: jawwalpay.v1/business/send_otp
{"msgId":"38441941756144","receiver":"009705••••0235","amount":"24",
 "errorCd":"1004","desc":"Bad SecureHash"}
POST /api/orders/jawwal/send-code → 422
```

الزبون يرى «تعذّر إرسال الرمز».

## ما يعنيه هذا بالضبط

| ما كنا نشك فيه | الحالة |
|---|---|
| IP الخادم مسموح لدى جوال باي | ✅ سليم — الطلب وصلهم وردّوا عليه |
| اسم المستخدم وكلمة المرور | ✅ سليمة — `send_otp` لا تمر إلا بجلسة، والجلسة فُتحت |
| عنوان الإنتاج | ✅ سليم |
| **توقيع الطلب `secureHash`** | ❌ **هذا هو الخطأ الوحيد** |

دليل التاجر متناقض في طريقة بناء التوقيع: الفقرة تقول «رتّب حسب المفتاح»، ومثالها يرتّب حسب القيمة، والبصمة المطبوعة في المثال لا تتطابق مع أي من القراءتين. لذلك **لا يمكن حسم الصيغة بالقراءة**.

## الآن، دون انتظار النشر

الأمر الجديد غير موجود على الخادم حتى تُرفع تعديلات اليوم. حتى ذلك الحين يقوم بنفس العمل ملف مستقل لا يحتاج إلا الكود المنشور:

```sh
# انسخ محتوى docs/payments/jp-probe-standalone.php إلى:
nano /tmp/jp-probe.php
php artisan tinker /tmp/jp-probe.php
```

يجرّب الصيغ كلها على `get_balance` ويطبع الصيغة المقبولة، والنص الذي وُقّع، والبصمة.

## الحل الدائم: اسأل البوابة نفسها

```sh
php artisan jawwalpay:probe
```

- يجرّب **كل الصيغ الممكنة**: ما يُوقَّع (كل الحقول، أو بدون `lang`) × ترتيب حسب القيمة أو المفتاح × sha512/sha256/sha1/md5 × المفتاح كـ HMAC أو ملصوقاً في أول النص أو آخره × حروف صغيرة أو كبيرة.
- **احتمال قوي:** كثير من البوابات لا توقّع حقل `lang` رغم إرساله. فرق حقل واحد يكفي لرفض كل طلب بـ 1004.
- كل محاولة استدعاء لـ **`get_balance` فقط**: موقّع، للقراءة، **لا يحرّك أي مبلغ**.
- يتوقف عند أول صيغة تقبلها البوابة ويطبع أسطر `.env` جاهزة:

```env
JAWWALPAY_HASH_SORT=key
JAWWALPAY_HASH_ALGO=sha256
JAWWALPAY_HASH_MODE=append
JAWWALPAY_HASH_CASE=lower
JAWWALPAY_HASH_EXCLUDE=lang
```

ثم:

```sh
php artisan config:clear
php artisan jawwalpay:check        # يجب أن يمر get_balance
```

## إن لم تُقبل أي صيغة

يطبع الأمر الطلب الذي أرسلناه، والنص الذي وقّعناه، والبصمة الناتجة. أرسلوها كما هي لأحمد عمرو مع سؤال واحد: **هل يختلف النص الذي نوقّعه، أم طريقة التوقيع؟** ويبقى احتمالان:

- **المفتاح السري خاطئ لبيئة الإنتاج** — مفتاح التجربة لا يعمل على الإنتاج.
- يوقّعون **ترتيب حقول ثابتاً** لا مرتّباً، أو يُدخلون حقولاً نحذفها حين تكون فارغة.

## حتى يُحل

**أطفئوا «جوال باي (دفع مباشر)» من «حسابات الدفع»** في لوحة التحكم. عندها تختفي الطريقة من صفحة الدفع، ويختار الزبون طريقة تعمل بدل أن يصطدم برسالة «تعذّر إرسال الرمز».

الطرق الأخرى غير متأثرة: جوال باي (تحويل) وبال باي وبنك فلسطين لا تمر بالبوابة إطلاقاً.
