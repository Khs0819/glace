# 11 — كوبونات الخصم

**الأولوية:** متوسطة (مش مانعة، بس مخاطرة أمنية)
**Endpoints:** `POST /cart/apply-coupon`
**الحالة الحيّة (2026-08-31):** الكوبون بالكامل محسوب بالفرونت من جدول ثابت بالكود (`VALID_COUPONS` بـ`cartStore.ts`):

```ts
{ GLACE10: 10, GLACE20: 20, WELCOME5: 5, "1234": 15 }  // قيمة خصم ثابتة بالشيكل، مش نسبة
```

هاد خطر أمني بسيط (أي حد يفتح الكود يعرف كل الأكواد)، وما فيه تحقق من: تاريخ انتهاء، حد أدنى للطلب، عدد مرات الاستخدام، أو ربط الكوبون بمستخدم معيّن.

---

## `POST /cart/apply-coupon`

```json
// Request
{ "code": "GLACE10", "subtotal": 85 }

// 200 — كوبون صالح
{ "valid": true, "code": "GLACE10", "discount": 10, "message": "تم تطبيق الكوبون" }

// 200 — كوبون غير صالح (لسه 200 مش خطأ، بس valid:false)
{ "valid": false, "discount": 0, "message": "الكوبون غير صالح أو منتهي" }
```

- **مهم:** السيرفر هو مصدر الحقيقة للخصم — لازم `POST /orders` (شوف [`12-orders.md`](./12-orders.md)) يعيد التحقق من الكوبون وقت إنشاء الطلب الفعلي، مش يثق برقم `discount` جاي من الفرونت وبس. حالياً الفرونت بيحسب `discount` محلياً ويرسله جاهز — هاد لازم يتغيّر بحيث الطلب يرسل `couponCode` فقط والسيرفر يحسب الخصم بنفسه.
- **تحديث (2026-08-31):** الفرونت صار يدعم كوبونات بنسبة مئوية أيضاً — الاستجابة زي ما هي (`discount` دايماً رقم نهائي بالشيكل محسوب مسبقاً)، يعني سواء كان الكوبون عندكم بالباك اند نسبة أو مبلغ ثابت، لازم تحسبوا `discount` النهائي (= `subtotal * percentage / 100` أو المبلغ الثابت) وترسلوه جاهز بنفس الحقل. لا داعي لحقل `percentage` منفصل بالاستجابة.
