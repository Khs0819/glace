# 16 — صفحة الشروط والأحكام: محتوى HTML

**الأولوية:** منخفضة
**Endpoints:** `GET /terms`
**الحالة الحيّة (2026-09-01):** الأقسام ثابتة بالكامل بالكود (`src/hooks/terms/fetchTermsContent.ts`) — نقلها هون بيسمح لفريق الدعم يعدّل نص الشروط من لوحة التحكم (Filament) بدون نشر كود جديد.

---

## شكل البيانات

استجابة `GET /terms` هي **سلسلة نصية واحدة فيها HTML كامل** (مش مصفوفة أقسام)، تحتوي كل الأقسام مع عناوينها:

```json
"<h3>1. قبول الشروط</h3><p>...</p><h3>2. الحساب والطلبات</h3><p>...</p><ul><li>...</li></ul>..."
```

- استخدم فقط: `<h3>` للعناوين، `<p>` للفقرات، `<ul><li>` للقوائم، `<a href="...">` للروابط.
- ترتيب العناصر بالـHTML = ترتيب العرض بالصفحة.
- لا يوجد pagination أو حقول إضافية — السلسلة نفسها هي كل المحتوى.

## `GET /terms`

مثال مختصر عن الشكل المتوقع (الأقسام الحالية الثمانية: قبول الشروط، الحساب والطلبات، طرق الدفع، التوصيل والاستلام، إلغاء الطلبات، المحفظة الإلكترونية، التعديلات على الشروط، التواصل معنا):

```json
"<h3>1. قبول الشروط</h3><p>استخدامك لتطبيق جلاسيه الأمير...</p><h3>8. التواصل معنا</h3><p>لأي استفسار... <a href=\"/contact\">تواصل معنا</a> ...</p>"
```

## ⚠️ تنبيه أمني مهم: Sanitization

الفرونت إند **يمرّر هاد الـHTML مباشرة إلى `dangerouslySetInnerHTML`** بعد تنقيته بمكتبة `isomorphic-dompurify` (انظر `TermsPanel.tsx`). هاي طبقة حماية إلزامية بالفرونت **حتى لو المصدر (Filament) موثوق به إدارياً**، لأنو:

- أي حساب Filament مخترق أو خطأ بشري بكتابة HTML خام ممكن يحقن `<script>` أو `onerror=` أو أي payload تاني.
- الفرونت ما بفترض إن الباك اند نضّف المحتوى — التنقية عندنا مستقلة تماماً.

**رجاءً طبّقوا تنقية مماثلة بالباك اند كطبقة دفاع إضافية** (مثلاً `HTMLPurifier` أو مكتبة sanitize بـLaravel) قبل حفظ المحتوى أو إرجاعه، لكن **بلاش تعتبروا هيك بديل عن تنقية الفرونت** — الاثنين لازم يشتغلوا مع بعض (defense in depth).
