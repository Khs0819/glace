# طرق الدفع من لوحة التحكم، وسبب رفض الشحن

**التاريخ:** 2026-09-22

## 1) `GET /api/payment-accounts` — الطرق المفعّلة فقط، مع الاسم

- يرجّع **كل طريقة مفعّلة** في «حسابات الدفع»: نقداً، بطاقة، جوال باي الآلي، جوال باي تحويل، بال باي، بنك فلسطين.
- **الطريقة المطفأة لا تظهر إطلاقاً.**
- حقلان جديدان:

| الحقل | المعنى |
|---|---|
| `displayName` | الاسم الذي كتبه المدير في «الاسم الظاهر للزبون». **يغيب إن لم يُكتب** — استخدموا تسميتكم الافتراضية |
| `type` | `transfer` (تحويل برفع إشعار) · `gateway` (جوال باي الآلي) · `counter` (نقداً أو بطاقة) |

```json
[
  { "method": "cash",   "type": "counter", "displayName": "كاش عند الاستلام" },
  { "method": "visa",   "type": "counter" },
  { "method": "jawwal", "type": "gateway", "displayName": "جوال باي الآلي (أسرع طريقة جوال باي)" },
  {
    "method": "palpay", "type": "transfer", "displayName": "بال باي",
    "holderName": "جلاسيه الأمير", "primaryLabel": "رقم المحفظة", "primaryValue": "0599999978",
    "qrImage": "https://back.glaceelameer.com/storage/payment-accounts/palpay.png"
  }
]
```

- **تفاصيل الحساب** (`holderName`, `primaryLabel`, `primaryValue`, `secondaryLabel`, `secondaryValue`, `bankName`, `accountNumber`, `qrImage`) تُرسل لطرق التحويل فقط. النقد والبطاقة لا حساب لهما.
- **أسماء الحقول لم تتغيّر.** المثال في ملفكم يستخدم `accountLabel` و`accountValue` و`iban`، والأسماء الفعلية هي `primaryLabel` و`primaryValue` و`secondaryValue` (الـ IBAN في الحقل الثانوي). لم أغيّرها حتى لا تنكسر الواجهة الحالية.

### تنبيه للفرونت: الرجوع الافتراضي

ملفكم يقول إن صفحة الدفع ترجع إلى «جوال باي (آلي)» إذا أُطفئت الطريقة المختارة. **جوال باي الآلي نفسه يصل مُطفأً** حتى تُجرَّب البوابة على الإنتاج، فقد لا يكون في القائمة أصلاً. ارجعوا إلى **أول طريقة في القائمة** بدل طريقة ثابتة.

### الخادم يطابق القائمة

- `POST /orders` يرفض الطريقة المطفأة: `422` في `errors.paymentMethod`.
- `POST /wallet/topup-requests` يرفضها أيضاً: `422` في `errors.method` = «طريقة الشحن غير متاحة حالياً».

## 2) `GET /api/wallet/topup-requests` — سبب الرفض

حقل جديد `rejectionReason`: نص السبب كما كتبه المراجع عند الرفض.

```json
{ "id": 42, "amount": 500, "method": "palpay", "status": "مرفوض",
  "rejectionReason": "الصورة غير واضحة، يرجى رفع صورة أوضح للإشعار" }
```

- يظهر **فقط** حين `status = "مرفوض"`. في غيرها يغيب الحقل، حتى لو كتبت الإدارة ملاحظة داخلية على طلب مقبول.
- السبب إجباري عند الرفض في اللوحة، والنموذج ينبّه المراجع أن الزبون سيقرؤه.

## في لوحة التحكم

- **حسابات الدفع:** خانة جديدة «الاسم الظاهر للزبون»، وعمود لها في الجدول. مفتاح «مفعّل» يشرح أن المطفأة تختفي من صفحة الدفع وشحن المحفظة.
- **طلبات الشحن:** خانة «سبب الرفض» تنبّه أن النص يظهر للزبون كما يُكتب.
