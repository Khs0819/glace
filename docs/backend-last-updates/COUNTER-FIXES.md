# تصحيحات الأسبوع الأول — الكاشير، السائق، الاسترداد، التوصيل المجاني

**التاريخ:** 2026-09-21

## للفرونت

### مناطق التوصيل — `GET /api/addresses/delivery-zones`

حقلان جديدان لكل منطقة:

```json
{ "id": "rimal", "name": "الرمال", "fee": 0, "freeDelivery": true, "regularFee": 10 }
```

| الحقل | المعنى |
|---|---|
| `fee` | ما يدفعه الزبون فعلاً — `0` حين يكون التوصيل مجانياً |
| `freeDelivery` | `true` حين تكون المنطقة على توصيل مجاني |
| `regularFee` | الرسوم المعتادة، تظهر فقط حين `freeDelivery = true` (لعرضها مشطوبة) |

**المطلوب:** حين `freeDelivery = true` اعرضوا «مجاني» في سطر التوصيل بدل `0.00 ₪`.

### الطلب — `GET /orders`, `GET /orders/{id}`, `POST /orders`

حقل جديد `freeDelivery` (bool): `true` لطلب توصيل رسومه صفر. نفس الاستخدام: «مجاني» بدل `0.00`.

الخادم يحسب الرسوم بنفسه من المنطقة؛ ما يرسله الفرونت لا يؤثر.

## للوحة التحكم

- **تعيين/تغيير السائق** متاح في أي مرحلة ما عدا الإلغاء والاسترداد — حتى بعد «تم الاستلام». تغيير السائق ينقل أجرة التوصيل للسائق الجديد. لا يمكن تغيير سائق حُوِّلت له أجرة هذا التوصيل.
- **لا يُغلق طلب توصيل بدون سائق:** «تم الاستلام» لا تظهر قبل تعيين سائق، في شاشة الكاشير وصفحة الطلبات.
- **تصحيح الحالة:** زر يُرجع الطلب لحالة سابقة بعد خطأ (مثلاً «تم الاستلام» بالخطأ، أو «ملغي» على البطاقة الخطأ). متاح للمحاسب والمدير. غير متاح لطلب مسترد لأن المال أُعيد فعلاً.
- **«مسترد» لم تعد حالة تُختار.** الاسترداد من زر «💸 استرداد المبلغ» على الطلب المدفوع:
  - إلى المحفظة أو نقداً ← فوري، والطلب يصبح «مسترد».
  - تحويل (جوال باي/بنك فلسطين/بال باي) ← يُضاف لقائمة **طلبات الاسترداد** بوسم «استرداد طلب»، والطلب «ملغي» حتى يُرفع إشعار التحويل، فيصبح «مسترد».
- **دفعات السائقين:** صفحة جديدة تعرض كل تحويل لسائق مع إشعاره والتوصيلات التي شملها.
- **الزبائن:** فلتر «لديهم رصيد في المحفظة».
- **مناطق التوصيل:** مفتاح «توصيل مجاني» لكل منطقة، في النموذج وفي الجدول مباشرة، دون مسح الرسوم الأصلية.
- **الفاتورة:** العنوان نوع الطلب وحده — «توصيل» / «استلام تيك أوي» / «تناول الآن». التوصيل المجاني يُطبع «توصيل مجاني».

## الصلاحيات

| | مدير | محاسب |
|---|---|---|
| الطلبات، الكاشير، السائقون، الاسترداد، تصحيح الحالة | ✓ | ✓ |
| حسابات الدفع | ✓ | ✗ |
| حذف الورديات | ✓ | ✗ |
| مستخدمو اللوحة (إضافة حسابات وتغيير الصلاحيات) | ✓ | ✗ |
| مواعيد العمل وفتح/إغلاق المتجر | ✓ | ✗ |

الحسابات الحالية كلها «مدير». أضيفوا حسابات المحاسبين من **الطلبات ← مستخدمو اللوحة**. لا يمكن حذف آخر مدير أو تحويله لمحاسب.

## حد النقد للمحاسب

**المحاسب لا يستلم أكثر من 200 ₪ نقداً في الطلب الواحد.** يُحسب على المبلغ المستلَم فعلاً باليد، لا على إجمالي الطلب وحده:

| الطلب | المستلَم | المحاسب | المدير |
|---|---|---|---|
| 150 ₪ | 150 | ✓ | ✓ |
| 150 ₪ | 200 (باقي 50) | ✓ | ✓ |
| 150 ₪ | 220 (باقي 70) | ✗ | ✓ |
| 250 ₪ | 250 | ✗ | ✓ |

- ينطبق على الدفع **نقداً** فقط، لا على البطاقة أو التحويل.
- المدير بلا حد على المستلَم، لكن حد الباقي (199 ₪) يسري على الجميع.
- يُطبَّق على الأزرار الثلاثة لاستلام النقد في شاشة الكاشير. زر «استلام + طلب استرداد» لم يكن يطبّق حد الباقي أصلاً، وصار يطبّقه.
- يمكن تغييره عبر `GLACE_ACCOUNTANT_MAX_CASH` في `.env`.

## كلمة سر منسية

```sh
php artisan user:password                     # يعرض من يستطيع الدخول
php artisan user:password owner@example.com   # يسأل عن كلمة سر جديدة، أو يولّد واحدة ويطبعها
```

رابط «نسيت كلمة السر» بالبريد لا يعمل لأن الخادم لا يرسل بريداً (`MAIL_MAILER=log`). المدير يستطيع أيضاً تغيير كلمة سر أي مستخدم من «مستخدمو اللوحة».
