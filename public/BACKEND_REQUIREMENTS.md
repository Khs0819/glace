# متطلبات الباك اند — المنيو

**آخر تحقق فعلي مقابل `https://glace-bzjj.onrender.com/api` — 2026-08-09**

هذا الملف يحدد بالضبط: المبدأ اللي بنشتغل عليه، إيش الباك اند عامله فعلاً، وإيش الناقص.
كل رقم هنا مأخوذ من فحص آلي للـAPI الحي، مش تقدير.

---

## 1. المبدأ الأساسي

> **الهيكلية ثابتة في الفرونت. الداتا متغيرة وتيجي من الباك.**

سيناريو عرض كل منتج (ترتيب الخطوات، شكل الويزرد) **قالب ثابت** مكتوب في الفرونت
ولا يتغير. الباك اند **يملأ الخانات** بالبيانات.

| | مثال |
|---|---|
| 🔒 **ثابت** (الفرونت) | بوظة كاسة: حاوية ← حجم ← عائلة نكهة ← كرات ← بسكوت ← كمية |
| 🔄 **متغير** (الباك) | أسعار الأحجام، قائمة النكهات، الصور، التوفّر |

نفس الكلام على بوظة عائلي، براد، براد بوظة، وميلك شيك — **السيناريو ما يتغيرش**،
البيانات بس هي اللي تتغير.

**النتيجة العملية:** الباك ما يقدرش يضيف/يشيل خطوة من الويزرد، ولا يغيّر نوع القالب.
لكنه يتحكم بالكامل في: الأسعار، النكهات، الصور، التوفّر، الأسماء.

### ⚠️ مفيش شبكة أمان

الفرونت **ما عندوش أي نسخة محلية** من داتا المنيو أو الهوم أو الفعاليات — اتشالت
بالكامل. يعني:

| الحالة | اللي بيحصل للزبون |
|---|---|
| الـAPI واقع أو بطيء | شاشة خطأ + زر «إعادة المحاولة» |
| رد بشكل غلط (حقل ناقص/نوع غلط) | نفس شاشة الخطأ — **الرد كله يترفض** |
| صف واحد بايظ في القائمة | **الرد كله يترفض**، مش بيتشال بصمت |
| كاتيجوري رجعت `[]` | «لا توجد منتجات» (رد صحيح، مش خطأ) |

اخترنا نرفض الرد كله بدل ما نتجاهل الصفوف البايظة عشان أي regression في الباك
يبان فوراً بدل ما يختفي. **جودة الرد مسؤولية الباك بالكامل** — مفيش fallback
يغطي عليها.

## 3. المطلوب بالتفصيل

### 3.1 النكهات — **داخل المنتج، مش endpoint منفصل** 🔴

> **قرار التصميم:** لا يوجد `GET /menu/flavors`. النكهات تيجي **مع المنتج نفسه**
> في `GET /menu/products/{slug}` تحت مفتاح `flavors[]`.
>
> **ليه:** صفحة الطلب تعمل **request واحد** بدل اتنين، وكل منتج يقدر يعرض
> **مجموعة نكهات خاصة فيه** (مثلاً العائلي يعرض نكهات مش موجودة في الكاسة).

```
GET /api/menu/products/cup   →   IBuilderProduct  (فيه flavors[])
GET /api/menu/products       →   بدون flavors[]   ← مهم
```

⚠️ **قائمة المنتجات `/menu/products` ما تحتويش `flavors`** — وإلا الكتالوج يتكرر
على كل صف ويكبّر الرد بدون داعي. الـdetail بس.

```json
{
  "id": "b7f1c2a4-…",
  "slug": "cup",
  "kind": "builder",
  "name": "بوظة كاسة",

  "containerOptions": [ ... ],
  "sizes": [ ... ],
  "selectionMode": "repeatable",
  "flavorFamilies": ["classic", "special", "mix"],

  "flavors": [
    { "id": "chocolate", "nameAr": "شوكولاتة", "nameEn": "Chocolate",
      "image": "https://cdn.glace.ps/flavors/chocolate.png",
      "family": "classic", "available": true },

    { "id": "mango", "nameAr": "مانجا", "nameEn": "Mango",
      "image": "https://cdn.glace.ps/flavors/mango.png",
      "family": "classic", "available": false },

    { "id": "pistachio", "nameAr": "بيستاشيو", "nameEn": "Pistachio",
      "image": "https://cdn.glace.ps/flavors/pistachio.png",
      "family": "special", "available": true, "isPremiumMixFlavor": true }
  ]
}
```

`flavors` مطلوبة على منتجات `builder` اللي عندها `flavorFamilies` غير فاضية
(**كاسة، عائلي، براد بوظة**). `براد` ما عندهوش خطوة نكهات فما بيحتاجهاش.

**بنية الداتابيز المقترحة:** جدول `flavors` عام + جدول ربط
`product_flavor (product_id, flavor_id)` — كده النكهة تتعرّف مرة واحدة وتترّبط
بأكتر من منتج، والـAPI يعمل join ويرجّعها inline.

| الحقل | النوع | ملاحظات |
|---|---|---|
| `id` | string | slug ثابت وفريد |
| `nameAr` | string | الاسم المعروض تحت كرة النكهة |
| `nameEn` | string | مطلوب |
| `image` | string (URL) | صورة الكرة |
| `family` | enum | **`classic` \| `special` \| `stevia` فقط** — الفرونت يرفض أي قيمة تانية |
| `available` | boolean | `false` → الكرة تظهر رمادية بشارة «غير متوفر» |
| `isPremiumMixFlavor` | boolean | اختياري. `true` → يتسعّر بـ`premiumFlavorPrice` بدل `flavorPrice` |

**الداشبورد: إضافة وحذف وتعديل كامل** — مش مجرد toggle. الأدمن يقدر يضيف نكهة جديدة
بالكامل (اسم + صورة + عائلة) ويحذف أي نكهة. الفرونت ما بيفترضش أي `id` ثابت.

`stevia` تُعرض داخل بيكر الـ`classic` (مش عائلة منفصلة في الواجهة).

نقطة البداية المقترحة: الـ23 نكهة في [`reference/fake-data/menu.ts`](./reference/fake-data/menu.ts) → `FAKE_FLAVORS`
(منها `mango` و`flora` موقوفين، و`pistachio` premium).

### 3.2 الصور — رفع من الداشبورد 🔴

الأدمن يرفع صورة من لوحة التحكم، والباك يرجّع **URL حقيقي**.

مطلوب رفع صورة لـ:

| الكيان | الحقل | الحالة |
|---|---|---|
| النكهة | `flavors[].image` | لا توجد نكهات بعد |
| المنتج | `image` | ❌ `cdn.example.com` |
| عنصر flat-list | `items[].image` | ❌ **الحقل مش موجود خالص (0/69)** |
| الحاوية | `containerOptions[].image` | ❌ واحدة بس وهي placeholder |

الفرونت جاهز: أي رابط حقيقي يعدّي زي ما هو، وأي رابط ميت يتحوّل تلقائياً لـplaceholder
محايد. **مش محتاج أي تعديل كود لما الصور تشتغل.**

> ⚠️ شيلوا `https://api.example.com/api` من `servers:` في `swagger.yaml` — دي اللي سرّبت
> عُرف `example.com` للبيانات.

### 3.3 التوفّر — 3 مستويات ناقصة 🟠

مطلوب إضافة `available: boolean` لـ:

**(أ) الأحجام** — `ISizeOption.available`

```json
{ "id": "plastic-one", "label": "1 لتر", "maxBalls": 12,
  "containerId": "plastic", "available": false,
  "prices": [ ... ] }
```

> حالة عملية ذكرها العميل: في **بوظة عائلي** خطوة «اختر النوع والحجم» مدمجة
> (بلاستيك/فلين × 1/2 لتر و1 لتر). لازم نقدر نوقف **الفلين** لما مش متوفر.
> ده شغال حالياً على مستوى الحاوية (`containerOptions[].available`) ✅،
> بس مطلوب كمان توقيف **حجم بعينه** — مثلاً «1 لتر فلين» بس من غير «1/2 لتر فلين».

**(ب) المكسات** — `IMixRule.available` → يخفي «مكس» أو «سوبر مكس» لمنتج معيّن

**(ج) الكاتيجوري** — `IMenuCategory.available` → يخفي قسم كامل (مثلاً المشروبات الساخنة صيفاً)

**(د) الإضافات** — `IAddonOption.available` — ✅ موجودة أصلاً، تفضل زي ما هي

**قاعدة التوفّر:** العنصر الموقوف **يفضل يرجع في الـAPI** ويتعرض رمادي بشارة
«غير متوفر» — ما يختفيش. ده يسمح بإيقاف مؤقت بدون حذف.

### 3.4 المنتجات — flat-list جديد مسموح، builder ثابت 🟡

| النوع | الداشبورد يقدر يضيف؟ |
|---|---|
| `flat-list` (ميلك شيك، حلويات، مشروبات، كنافة…) | ✅ **نعم** — السيناريو واحد متكرر، الفرونت يرندره تلقائياً |
| `builder` (كاسة، عائلي، براد، براد بوظة) | ❌ **لا** — 4 فقط، كل واحد سيناريو مفصّل بإيد |

لو الأدمن ضاف منتج flat-list جديد لازم يبعت: `kind: "flat-list"`, `slug` فريد,
`categoryId` موجود, `name`, `image`, `sortOrder`, `available`, `items[]`
(و`mixes[]` اختياري). الفرونت يرندره من غير أي deploy.

### 3.5 توحيد الـ404 🟡

```
GET /api/menu/products/{unknown}   →  404   (حالياً: 200 + {})
```

خليه زي `/api/events/{id}` بالظبط. الفرونت يتعامل مع الاتنين دلوقتي، بس التوحيد أنضف.

### 3.6 معرّفات ثابتة للعناصر (`items[].id`) — **جديد** 🔴

**المشكلة:** المكسات كانت تشاور على العناصر بحقل اسمه `flavorOptionIds` وجواه
**نصوص عربية** (`["نوتيلا","لوتس","بيستاشيو"]`) بتتطابق مع `items[].label`.

ده بيتعارض مع اللي اتفقنا عليه: **الأسماء متغيرة 🔄 من الداشبورد**. لو الأدمن غيّر
«نوتيلا» لـ«نوتيلا سبيشال»، المكس بيقع **بصمت** — من غير أي error، الطعم يختفي من
المودال بس.

**الحل:** كل عنصر ياخد `id` ثابت، والمكس يشاور عليه.

```json
{
  "slug": "pancake",
  "kind": "flat-list",
  "items": [
    { "id": "nutella",   "label": "نوتيلا",   "price": 11, "available": true },
    { "id": "lotus",     "label": "لوتس",     "price": 13, "available": true },
    { "id": "pistachio", "label": "بيستاشيو", "price": 17, "available": true,
      "isPremiumMixFlavor": true }
  ],
  "mixes": [
    { "id": "mix", "label": "مكس (اختر طعمين)", "pick": 2,
      "basePrice": 14, "flavorPrice": 7, "premiumFlavorPrice": 11,
      "itemIds": ["nutella", "lotus", "pistachio"] }
  ]
}
```

| | قديم | جديد |
|---|---|---|
| الحقل | `flavorOptionIds` | **`itemIds`** |
| المحتوى | labels عربية | **`items[].id`** |
| تغيير الاسم | ❌ يكسر المكس | ✅ ما يأثرش |

**قواعد الـ`id`:**
- فريد **داخل المنتج** (مش على مستوى المنيو كله) — `nutella` في البان كيك غير `nutella` في الكريب
- latin slug، ثابت، **ما يتغيرش أبداً** حتى لو الاسم اتغير → 🔒 ثابت
- كل `itemIds` لازم تحل لـ`id` موجود في **نفس المنتج**

الـ69 عنصر كلهم عندهم `id` جاهز في
[`reference/fake-data/menu.ts`](./reference/fake-data/menu.ts) — استخدموها كـseed
مباشرة (متحقّق: كل الـids فريدة وكل `itemIds` بتحل صح).

> ⚠️ **شيم مؤقت في الفرونت:** لحد ما الباك يبعت `items[].id` و`mixes[].itemIds`،
> في دالة `normalizeProductIds()` في `src/hooks/menu/fetchMenuProducts.ts` بتشتق
> الـ`id` من الـlabel وبتقرا `flavorOptionIds` القديم. **تُحذف بالكامل** أول ما
> الباك ينزّل الشكل الجديد — دالة واحدة، حذفة واحدة.

### 3.7 الفرق بين «عنصر» و«كرة نكهة» — لبس شائع ⚠️

| | `items[]` (عنصر) | `flavors[]` (كرة نكهة) |
|---|---|---|
| مثال | عصير فراولة · ميلك شيك نوتيلا | كرة بوظة فراولة |
| السعر | ✅ **عنده سعر بنفسه** | ❌ **مالوش سعر** — السعر من الحجم |
| الشراء | يتضاف للسلة مباشرة | يتحط جوه كاسة/عائلي |
| النوع | `IProductVariant` | `IFlavorOption` |
| على مين | كل منتجات `flat-list` | `builder` بس (كاسة/عائلي/براد بوظة) |

نفس الاسم ممكن يكون الاتنين: «فراولة» عصير (عنصر بـ5₪) و«فراولة» كرة بوظة
(نكهة بلا سعر). **كيانين مختلفين.**

### `family` — تلات قيم فقط

```
classic  |  special  |  stevia
```

🔴 **مفيش نكهة عائلتها `mix` ولا `super-mix`.** الفرونت **يرفض** أي قيمة تانية ويرمي error.

- **`mix`** موجودة في `flavorFamilies` بتاعة المنتج — دي **تسعيرة**، مش نكهة
- **`super-mix`** موجودة كـ`IMixRule` على flat-list بس — مالهاش أي علاقة بالنكهات

| المنتج | `flavors[]` | `mixes[]` |
|---|---|---|
| كاسة · عائلي · براد بوظة | ✅ | ❌ |
| براد | ❌ | ❌ |
| **ميلك شيك** | ❌ | ❌ (عناصر مسطحة بس) |
| بيتزا · كريب · وافل · بان كيك · لقيمات | ❌ | ✅ mix + super-mix |
| كنافة | ❌ | ✅ mix فقط |

> الميلك شيك: «كلاسيك/سبيشال» **جزء من اسم العنصر** (`"كلاسيك شوكولاته"`)، مش حقل.

## 4. جدول الحقول: 🔒 ثابت مقابل 🔄 متغير

### 🔒 ثابت — يتحدد عند الـseed، **ممنوع في الداشبورد**

تغييرها يكسر سيناريو العرض:

| المجموعة | الحقول |
|---|---|
| هوية | `kind` · `slug` · `categoryId` |
| سلوك الويزرد | `selectionMode` · `flavorFamilies` · `includesIceCreamStep` · `hasExtraBiscuitAddon` |
| عناصر UI | `hasNotes` · `hasFavorites` · `hasImageZoom` · `inStoreOnly` |
| مفاتيح | `containerOptions[].id` · `sizes[].id` · `sizes[].containerId` · `mixes[].id` · **`items[].id`** · **`flavors[].id`** |
| قواعد | `mixes[].pick` (عدد الأطعمة المختارة) · `mixes[].itemIds` (تشاور على `items[].id`) |
| كاتيجوري | `icon` |

### 🔄 متغير — تحكّم كامل من الداشبورد

| المجموعة | الحقول |
|---|---|
| الأسعار | كل `price` · `basePrice` · `flavorPrice` · `premiumFlavorPrice` · خلايا `prices[]` · `iceCreamAddonPrices[]` |
| التوفّر | كل `available` على كل المستويات |
| النصوص | `name` · `label` · `description` · `nameAr` · `nameEn` · `pricingLabel` |
| الصور | كل `image` |
| الترتيب | `sortOrder` |
| الكتالوجات | النكهات (إضافة/حذف) · `items[]` (إضافة/حذف) · `addons[]` |
| حدود | `maxQty` · `maxBalls` ⚠️ |

> ⚠️ `maxBalls` ما بيغيّرش شكل العرض بس بيغيّر حد الاختيار — قابل للتعديل بحذر.

### ❗ نتيجة مباشرة على `brad`

بما إن `selectionMode` و`flavorFamilies` **ثابتة seed**، الباك لازم يبعتها بالشكل
المكتوب بالضبط أو **يحذفها تماماً** — مش `null` ولا `[]`.

```diff
- "selectionMode": null,
- "flavorFamilies": []
+ (الحقلان محذوفان بالكامل)
```
